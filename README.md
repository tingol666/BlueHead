# BlueHead

**把 Windows 电脑变成移动设备的蓝牙耳机。**

在电脑上听手机、平板的声音，并将电脑麦克风发送给移动设备，用于通话或支持蓝牙麦克风的应用。音频直接通过蓝牙传输，无需同一 Wi-Fi，无需安装移动端客户端。

[下载最新版](https://github.com/tingol666/BlueHead/releases/latest) · [使用指南](docs/UI_GUIDE.md) · [构建源码](docs/BUILDING.md) · [报告问题](https://github.com/tingol666/BlueHead/issues)

## 能做什么

- **接收媒体和双向语音**：播放移动设备的音乐、视频声音，使用电脑的扬声器、耳机和麦克风。
- **连接多台设备**：同时混合媒体声音，或在当前设备暂停后自动接替另一台已请求播放的设备。
- **独立音量与静音**：每台设备的播放、麦克风发送独立调节，另有总音量，范围均为 0%–200%。
- **切换电脑声音设备**：接收期间更换耳机、播放设备或麦克风；选择系统默认时自动跟随插拔和默认设备变化。
- **混入电脑声音**：可将其他电脑应用的声音与实体麦克风合并后发送，排除 BlueHead 自己播放的移动设备声音。
- **管理专用适配器**：在应用内备份原蓝牙驱动、启用 WinUSB 专用接收，或恢复系统蓝牙。

项目免费、开源；安装包自带 Python 和 .NET 运行环境，使用者无需另外安装。

## 开始之前

下载 **Windows x64** 版本。目前主要验证环境为 Windows 11 + Intel AX211。其他控制器及移动系统的支持情况取决于实际硬件、驱动和音频协议，不能仅凭蓝牙 5.x 版本判断。

BlueHead 提供两种接收方式：

| 方式 | 适合什么情况 | 需要准备什么 |
|---|---|---|
| 声音与麦克风 | 需要双向语音、编码选择、音量路由和多设备控制 | 一个由 BlueHead 专用的 USB HCI 蓝牙适配器，绑定 WinUSB |
| 仅接收声音 | 希望沿用 Windows 蓝牙驱动，接收媒体声音 | Windows 支持的蓝牙适配器，先在系统设置配对；编码和播放设备由 Windows 管理 |

**专用接收会占用所选适配器。** 如果使用电脑内置蓝牙，其原有耳机、键鼠等连接会断开；可另用一个受支持的 USB 蓝牙适配器。应用会先备份原驱动，再请求管理员授权；停止接收后可恢复系统蓝牙。

移动设备需要支持相应的 A2DP / HFP 功能。本项目尚未对 iOS、HarmonyOS 等平台作完整兼容性验收。

## 安装与首次连接

1. 从 [Releases](https://github.com/tingol666/BlueHead/releases/latest) 下载 `Setup-x64.exe` 安装包，或完整解压 `Portable-x64.zip` 绿色包，运行 `BlueHead.exe`。不要只移动其中的 EXE。
2. 点击首页 **设置蓝牙接收**，选择接收方式。需要麦克风时，按向导准备专用适配器；驱动操作会弹出 Windows 管理员授权。
3. 回到 **音频中心**，点击 **开始接收**。在移动设备蓝牙设置中连接界面显示的名称，并开启媒体和通话音频。
4. 播放音乐或开始通话。首页底部的音量按钮可调整总音量、静音或切换电脑声音设备；设备卡片的 **播放 / 麦克风发送** 控制该设备的两路音量。

出声方式与编码都在首页。默认优先高清；更换编码后按提示应用并重新连接。两台设备同时播放高清音频若断续，可改用 AAC，必要时选择最高 192 kb/s；也可使用 **单设备自动接替**。

关闭窗口默认保留在系统托盘。完全退出请右键托盘图标 → **退出**。需要恢复电脑系统蓝牙时，先停止接收，再进入 **蓝牙与驱动 → 恢复系统蓝牙**；后台无法启动时也可运行 `BlueHead.exe --recovery`。

详细操作见 [界面与操作](docs/UI_GUIDE.md) 和 [音量、码率与高级混合](docs/AUDIO_CONTROLS.md)。

## 音质与兼容范围

| 项目 | 当前支持 |
|---|---|
| 媒体编码 | SBC、AAC、aptX、aptX HD；实际结果取决于双方协商 |
| LDAC | 实验性、默认关闭；使用非 Sony 认证解码器 |
| 双向语音 | HFP：CVSD 8 kHz / mSBC 16 kHz，单声道；一次一个语音设备 |
| 多设备媒体 | 同时播放或单设备自动接替；本机 AX211 双 AAC 已有稳定播放记录，双 aptX HD 在该组合下存在丢包 |
| 录音与录像输入 | 取决于移动端应用是否选择蓝牙麦克风，电脑端无法强制指定移动应用的音源 |
| 电脑声音混合 | 需要 Windows build 20348 及以上，Windows 11 支持 |
| 音频处理 | 原生 C 回调、有界混音、SpeexDSP 软件重采样；共享 WASAPI 优先使用 Windows 格式转换 |

通话使用 HFP 语音编码，音质与媒体模式不同。默认媒体起播缓冲 60 ms、语音 30 ms；**这些设置不是蓝牙端到端延迟实测值**。

目前不支持 AVRCP、LE Audio / LC3、aptX Adaptive / Lossless 和同时多路语音桥接。没有声学回声消除；使用扬声器外放时，实体麦克风仍可能拾到声音，通话建议使用电脑耳机。

**1.2.4 的验证范围**：本版完成自动化和离线音频检查，未重新进行实机音频验收。1.2.3 的连续播放、双向语音、热切换和挂断恢复已有用户确认；具体证据及边界见 Release 附带的 `VALIDATION.md`，更新内容见 [CHANGELOG](CHANGELOG.md)。

## 数据与隐私

音频仅在本机实时处理，不录音、不上传声音。绿色版的配对和设置存放在 `data/`；安装版存放在 `%LocalAppData%\BlueHead\data`。升级请保留该目录，驱动恢复备份也不要手动删除。

提交问题时请附版本、Windows 版本、适配器型号及复现步骤。应用内可导出匿名诊断；不要公开配对密钥、原始日志、设备地址或完整驱动恢复记录。

## 开发与项目结构

界面使用 C# / WPF；Python 负责蓝牙协议和控制；C / C++ 负责实时音频回调、混音、重采样及系统采集。实时音频不经界面进程传递。

```text
bluehead/    蓝牙后台、控制接口与音频路由
desktop/     WPF 界面、Windows 系统接口、驱动辅助程序
native/      原生音频、启动器及 WinUSB 模板
vendor/      固定版本上游源码、来源与校验信息
tools/       构建、基准、诊断及发布工具
tests/       协议、编解码、生命周期和音频回归
installer/   安装、升级及卸载脚本
docs/        使用、架构、构建与测试说明
licenses/    第三方许可证
```

开发环境为 Windows x64、Python 3.13、.NET SDK 10.0.402、MSYS2 UCRT64 和 NSIS 3。依赖版本及上游提交已固定。完整步骤见 [构建说明](docs/BUILDING.md)；贡献前请阅读 [架构](docs/ARCHITECTURE.md)、[测试说明](docs/TESTING.md) 和 [贡献指南](CONTRIBUTING.md)。

仓库包含源码、必要的原生库和测试材料。安装包、绿色包及校验文件放在 Releases；构建缓存、私人数据和原驱动备份不属于公开源码。
