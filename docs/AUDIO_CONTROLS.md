# 音频路径、音量与实时数据

本页描述2.0.0候选。新的原生链路、Apple标准音频、AVRCP与LC3-SWB仍待完整新包真机验收；历史版本结果见CHANGELOG/AUDIT。

## 五类增益，标准音量另算

所有本地音量范围0%–200%，0%静音、100%不额外放大。设备上的两路与底部三个总控各有独立静音，取消静音恢复此前数值。

| 调节项 | 影响 |
|---|---|
| 每设备播放 | 该设备传到电脑的媒体及语音下行 |
| 每设备麦克风发送 | 混合完成后发给该设备的语音上行 |
| 总设备声音 | 所有设备在电脑播放的总增益及输出设备选择 |
| 总电脑麦克风 | 实体麦克风采集增益及麦克风选择 |
| 总电脑声音 | 高级混合启用后，其他电脑应用声音的发送增益 |

```text
电脑播放 = Σ(设备下行 × 该设备播放增益) × 播放总增益
发送到设备 = (实体麦克风 × 麦克风总增益
              + 其他电脑应用 × 电脑声音总增益) × 该设备上行增益
```

200%表示数字增益，不能恢复失真的原始信号；混合峰值受数字范围限制。每设备接收增益与上行增益互不替代。

AVRCP标准绝对音量为0%–100%，作用于设备音频链路，**与上述0%–200%本地增益分开保存**。例如本地175%时，对端改标准音量仍保留175%；实际声音会同时受标准音量影响。卡片详情只读显示标准音量，未报告则显示未知，没有额外slider。界面优先读取volume字段，并兼容standard_volume状态。

## 双向语音与电脑声音混合

默认只发送实体麦克风。开启首页“混入电脑声音”后显示第三路总控，把其他应用声音与麦克风合并作为上行。电脑麦克风弹层的“暂停发送到设备”同时暂停两者，单路静音只改变该路增益。

电脑声音采用WASAPI进程排除模式：排除BlueHead后台及子进程树，而非先抓全局输出再减PCM。它要求Windows build20348+，普通Windows10 22H2不提供此能力。渲染必须留在被排除进程树中。

数字排除不能阻止实体麦克风从空气拾到扬声器声音；当前无声学AEC，建议通话使用电脑耳机。录音/录像使用蓝牙麦克风也走HFP语音链路，但移动端应用必须支持并选择，电脑不能强制接管其输入。

HFP按对端协商使用CVSD8kHz、mSBC16kHz或LC3-SWB32kHz单声道。LC3-SWB需双方支持，不是完整LE Audio，也不是蓝牙5.3的必备功能；不支持时应回退可用语音codec。一次一个上行语音对象，不提供多设备电话会议桥接。

## 热切换与缓冲

播放和麦克风选择位于对应总音量弹层，可在接收期间切换。默认设备跟随系统；指定设备按稳定endpoint ID跟踪，消失时明确回退。候选先准备、旧消费者停止后新消费者才启动，避免两路播放回调竞争同一队列。蓝牙连接不因电脑端设备切换而重建。

输出优先48kHz共享WASAPI及Windows格式转换；系统不接受时使用端点时钟和原生SpeexDSP回退，不改变Windows系统格式。原生采集队列有界，积压或重启时不重放旧语音。

默认媒体60ms、语音30ms为预缓冲配置，不是端到端延迟。降低缓冲可能更容易断续，不能仅因原生化就假定任意设备都能用极小值。

## 设备卡片的实时数据

媒体和语音共用一条协议/频率/码率信息，例如：

```text
A2DP / aptX HD · 48 kHz · 576 kb/s
HFP / mSBC · 16 kHz · ↓ 60.8 kb/s  ↑ 60.8 kb/s
HFP / LC3-SWB · 32 kHz · 实际上下行码率
```

码率来自近期编码负载，不是固定标称标签，也不是解码后的PCM、蓝牙空中总流量或网络带宽。媒体排除RTP/媒体封装；语音按codec负载统计。实际值随包活动变化，停止后回落。Windows管理接收方式无法取得专用后端的这层信息，显示由系统管理。

“详情”显示包速率、缓冲、重同步、丢包、麦克风/电脑声音状态；AVRCP可用时另显示曲名、专辑、位置和标准音量。未知值不冒充零延迟或已支持。

## 多设备策略

多设备模式混合媒体；单设备模式选择一个来源，向其他媒体请求暂停。已请求播放但被本程序暂停的来源可等待接替，用户主动暂停的来源取消等待。切换依据包活动，安静段落不会误切。

某些适配器/设备组合的双高清无线流会丢包。历史AX211对照中双AAC稳定而双aptX HD受损，这只说明该组合，不能推导所有控制器的极限或承诺2.0.0已复测。首页可明确选择AAC及192kb/s上限并重连，或改单设备接替；不会偷偷改写手动codec偏好。

受损竞争来源暂时淡出隔离、持续恢复后淡入，保护状态可见且不改用户增益。自动化能检查门控和恢复策略，无线稳定性仍需最终包真机验证。
