# 音量、采集来源与实时详情

## 在哪里调节

点击音频中心底部“设备声音”“电脑麦克风”或“电脑声音”，打开对应弹层，选择声音设备并调节音量。开启“同时发送电脑声音”后才显示第三项；未开启时保持两项。

| 项目 | 影响范围 |
|---|---|
| 每设备“播放” | 该设备传到电脑的媒体及语音声音 |
| 每设备“麦克风发送” | 混合完成后发给该设备的声音 |
| 总“设备声音” | 所有设备在电脑播放的总增益、电脑播放设备 |
| 总“电脑麦克风” | 电脑麦克风选择、麦克风发送增益 |
| 总“电脑声音” | 其它电脑应用的采集来源、发送增益 |

本地增益均为 0%–200%。100% 不额外放大，0% 静音；静音按钮再次点击恢复此前数值。200% 是数字增益，不能恢复已经失真的原信号。AVRCP／LE VCS 的标准设备音量单独保存，不改写这些增益。

```text
电脑播放 = Σ(设备声音 × 每设备播放增益) × 设备声音总增益
发送到设备 = (电脑麦克风 × 麦克风总增益
              + 电脑应用声音 × 电脑声音总增益) × 每设备麦克风发送增益
```

麦克风弹层的“暂停发送麦克风＋电脑声音”同时暂停两路发送，不影响收听设备。单路静音只调节该路。

## 选择电脑声音来源

先在首页打开“同时发送电脑声音”，再点底部“电脑声音”，在“电脑声音采集来源”中选择：

- **全部应用声音（排除 BlueHead）**：默认选项。Windows 在采集阶段排除 BlueHead 原生后台及其子进程，采集其它应用在各播放设备上的声音。不是先录入设备声音再做数字相减。
- **某个电脑播放设备**：只采集这个耳机／扬声器正在播放的声音。Windows 的按设备回环没有进程排除能力，因此它必须与 BlueHead 的“设备声音”播放设备分开。可以让其它应用在扬声器上播放，BlueHead 设备声音在另一副耳机上播放。

指定来源与 BlueHead 输出冲突时，切换请求会失败并保留原来源；之后输出热切换导致冲突时，原生发布门先关闭、清空该路待发送数据，再开始新输出，避免数字返送。该路会提示暂停，麦克风继续工作。把来源改为默认选项或改用不同的播放设备即可恢复。

指定来源被拔出时，不擅自改采另一台设备；保留所选来源，按端点恢复策略重试，或由你选择新来源。列表会随插拔更新。全部应用模式不绑定某个物理播放设备。

电脑声音混合要求 Windows build 20348+，通常为 Windows 11。数字排除无法阻止实体麦克风从空气拾到外放声音，当前没有声学 AEC，通话建议使用电脑耳机。

## 语音、录音和录像

设备调用电脑麦克风时会使用 HFP 或 LE Audio 上行，不限于电话。应用需要支持并选择蓝牙麦克风；电脑不能强制改变对端应用路由。一次向一个设备发送，语音编码由双方自动协商。

默认“通话／语音保护”会在使用麦克风时暂时断开其它设备并阻止新连接，结束后可重新连接。它覆盖支持的语音编码，不只针对 mSBC。

## 热切换与音质

电脑输出、麦克风及电脑声音来源可在接收中更换，不重建蓝牙。默认输出／麦克风跟随系统；指定的输出／麦克风消失时按页面提示临时回退，并在恢复后重新采用原选择。电脑声音来源采用上述更严格的规则。

输出优先端点实际共享格式，媒体保留原采样率和浮点 PCM；只有采样率不匹配或独立时钟需要时做 SRC。新端点先准备、旧消费者停止后新消费者才启动，不让两个回调同时消费同一队列。

## 实时详情显示什么

设备行显示“协议／编码 · 采样率 · 实际压缩负载码率”，语音同时显示上下行码率；它不是开发者选项中的最大码率，也不是 USB／无线总开销。

详情中的“包/s”来自原生接收计数按经过时间计算，暂停或一段时间没有新音频后归零。“实际缓冲”是当前 PCM 排队量，不是配置的目标或协商预算；计数缺失时不伪造零值。解码补偿、重同步和丢包是当前会话累计值，零也可能表示没有发生过。

LE Audio 的“协商播放时延”来自 QoS 呈现预算，与当前实际缓冲分开。所有这些数字都不能单独代表端到端声学延迟。
