# 软件音频内核重构（2.1.1）

音频内核阶段只修改源码、编译所需原生组件并运行离线验证，不更改驱动、不做实机测试。用户随后指定的顺序是：内核验证完成后，依次完成异常恢复、架构整理，最后构建并部署 2.1.1；GitHub 发布须等用户实测同意。既有 `de00d73` 是重构前基线，其验证结果不能直接当作本轮新内核的结果。

## 核心问题与实施方向

| 当前软件路径 | 软件风险 | 重构方向 |
| --- | --- | --- |
| 捕获浮点 → S16 → 上行浮点混音 → S16 → 语音 SRC/编码 | 不必要的重复量化，低电平细节提前丢失 | 内部浮点 PCM；仅在编解码器或协议要求的边界量化，旧 S16 ABI 作为适配层保留 |
| 解码完成时间被用作 PCM 到达时间 | 原生解码线程停顿会污染到达抖动估计 | 统一来源帧位置、接收到达时刻与呈现进度的契约，避免混淆各方向时钟 |
| 媒体/语音解码器和通用渲染器各有缺口预测 | 同一缺口可能被二次修复，恢复重复或增加延迟 | 明确每路缺口预测的唯一所有者，呈现短缺与编码丢帧分开计数、恢复 |
| 音频回调在第一次缺口中搜索周期 | 最坏耗时与普通块相差很大 | 周期分析移到非回调路径；实时回调只做有界采样、混合、包络和输出 |
| 格式转换、漂移校正和滤波状态分散 | 重复转换、切换残留、块长依赖 | 共用时钟/状态契约；检查 unity 直通、滤波状态、静音与重置边界，合并有证据可消除的转换 |

现有单一原生 USB/HCI 所有权、双向语音、麦克风录音、多设备混音/接替和输入输出热切换是必须保持的行为。不会通过降低协商媒体编码、降低对端采样率或明显增大缓冲来取得通过结果。

## 验证约束

- 正常 unity 路径保持混合频率、瞬态与立体声相位；检查块长无关性和低电平信号，不能仅检查“非零音频”。
- 对照旧量化路径与新浮点路径，覆盖 44.1/48/96/192 kHz 捕获、语音编码、极低电平、增益及过载边界。
- 记录实际转换次数、缺口/恢复次数、时间线位置、软件队列与处理预算；一次缺口不能增加两份音频时长。
- 原生线程停顿与 Python 停顿分别注入；检查延迟任务、突发队列、旧会话数据和停止/重开。阻塞注入验证软件行为，不用于归因硬件或无线环境。
- 保留丢包、乱序、抖动、RTP 回绕、长期时钟偏差及双工/多设备的软件回归。
- 明确记录验证的源码提交与原生文件摘要。本轮没有实机听感结论，也不以旧候选的测试结果冒充新内核结果。

## 参考

- [WebRTC NetEq](https://webrtc.googlesource.com/src/+/refs/heads/main/modules/audio_coding/neteq/g3doc/index.md)：包插入、呈现时钟、过期包处理与单次缺口决策的职责分工；不照搬其语音时间伸缩到一般音乐。
- [SpeexDSP resampler](https://www.speex.org/docs/manual/speex-manual/node7.html#SECTION00760000000000000000)：连续有状态转换，浮点与整数入口的边界。
- 已固定的 PipeWire 时钟控制、miniaudio 与现有 LC3/SpanDSP，许可和版本记录继续保留。

## 内核阶段完成记录

已落实浮点内部 PCM、48 kHz 帧位置／原始到达时刻／呈现进度契约、共用时钟控制器、各路缺口所有权和过期数据处理。生产媒体、语音和捕获输入明确声明角色；通用周期搜索仅保留为离线旧策略对照。解码器负责编码丢帧预测；播放回调只做有限包络和恢复交叉淡入，不再对同一缺口做第二次周期搜索。长停顿恢复只在恢复边界丢弃过期积压，正常播放仍由平滑时钟校正跟随，不做周期性跳样。

捕获、上行混音、语音编解码桥接使用归一化 float，保留原 S16 ABI 适配层；CVSD/mSBC 仅在低采样率编解码边界量化，LC3 使用 float 入口。48 kHz 立体声解码只做必要的格式归一化，不再经过无须使用的 swresample。真正跨采样率的连续 Speex/SWR 转换仍保留质量配置和状态。

以上是离线软件行为证据，耗时包含 Python→C 测量开销，不是蓝牙端到端延迟。没有降低协商编码、对端采样率或扩大原有缓冲上下限。任意线程长期无法运行时不能恢复不存在的样本；检查目标是隔离影响、维持其他方向、避免重复播放，并平滑回到新鲜音频。

本机可复查的原始记录位于 `work/core-timeline-final.xml`、`work/float-clock-final.xml`、`work/clock-timeline-core.json`、`work/core-timeline-soak.json` 和 `work/quality-cost-timeline-{core,generic}.json`；合成回放报告含实际原生文件 SHA-256。它们是本地构建记录，不随源码发布用户数据或临时目录。异常恢复与架构阶段须各自验证，不能借用本阶段结果宣称完成。
