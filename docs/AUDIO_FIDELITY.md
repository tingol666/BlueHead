# 音频保真专项：2.1.2

## 信号基准与约束

基准是协议解码器输出的 PCM。普通音量、无缺口、未过载、无需改变采样率的路径，
对齐固定延迟后应保留每个样本；必要重采样以独立数学信号对照频响、误差、噪声与相位。
语音以送入协议编码器前的 PCM 为另一端边界。编解码、Windows 混音与实际声卡的行为单独标识。

96 kHz LDAC 在输出能力允许时保留 96 kHz，避免先变成 48 kHz 再升回；
更高采样率以实际来源和输出能力为准，架构不能依赖全链路固定 48 kHz。
必要的格式转换保持 float，直到最终输出或编码器确实需要整数格式。

前几轮的连续性约束仍有效：唯一 USB/HCI 所有者、原生实时收发、统一时间基准、
单一缺口补偿责任、期限／过期隔离、有界回调、事务式热切换及分类恢复。
音质改进也必须通过计算耗时、缓冲、漂移、阻塞与丢包测试，不能靠降低协商编码、
持续扩大缓冲或增加重复预缓冲实现。

## 分阶段工作

1. 记录现有链路、转换次数和独立信号基线；保留原生库摘要，后续逐项对照。
2. 整理采样率／格式契约，让高采样率解码到输出避免不必要的中间降采样；
   混合不同来源、端点热切换和语音上下行继续各自遵循正确时钟。
3. 根据基线优化插值精度、重采样、声道映射和量化边界；正常信号透明，过载才保护。
4. 将补偿、淡变和恢复影响限制在明确事件窗口，保证窗口外样本不被长期修改。
5. 合并信号、性能及协议／生命周期验证，完成包检查后部署并发布；每阶段通过后才继续下一步。
6. 全部音频阶段通过后，统一系统共用／专用接收的界面状态、可执行操作和跨页引导，再发布。

## 第一阶段记录

基线修订：`de91c61`（固件／驱动修复已完成，持续音频处理尚未改动）。
开发工具 `tools/audio_fidelity_audit.py` 使用真实原生库及生产插值代码，不打开声卡、
麦克风或蓝牙，不保存原始样本。固定随机输入含独立声道、24-bit 步进、低电平与瞬态。

- 48 kHz、100% 增益、无需时钟修正时，41,000 个对齐样本与输入数值完全相等，固定延迟 72 帧。
- 64-tap 分数延迟插值的 DC 最大误差约 `4.77e-7`，20 kHz 以内最大复数误差约 `1.56e-6`。
  22 kHz 的最差相位增益约 `-0.0845 dB`；这些是后续精度／频带优化的实测对照。
- 96 kHz LDAC 解码器本身能以 96 kHz 直接保留 PCM，RTP 媒体封装不必额外重采样。
  当前运行时的媒体工作线程却指定 48 kHz，是需要消除的中间格式限制。
- CVSD/mSBC 使用 SpeexDSP quality 5，媒体输出回退使用 quality 10；将按频带、群延迟和最坏耗时评估，
  不直接把所有路径改成最长滤波器。

数值报告放在本地 `work/`，公开源码只保留可复现工具、测试与约束。每阶段实际结果更新在此，
完整交付的最终范围以 Release 的 VALIDATION.md 为准。

## 第二阶段记录

媒体工作线程和隔离 LDAC 进程保留协商采样率的 float PCM。各来源有独立原生帧环与
播放位置，RTP／到达时间仍使用共同的 48k 时间单位。输出端点的不可变转换方案在控制侧准备，
必要采样率转换与微小漂移校正合并在一次插值中；回调不分配内存、不设计滤波器。
队列上下限、PI 控制周期、缺口及增益／限制器窗口按真实时长换算，诊断的公共帧计数仍用 48k 单位，
另列 `pcm_rate`。多设备供给保护按每个来源的采样率判断，不再假定每秒固定 48,000 帧。

WASAPI 优先使用端点的实际共享格式，保留拒绝原生协商时的兼容回退；不启用 miniaudio 通用 SRC。
96k LDAC 配合 96k 共享端点可保留原采样率；端点为 48k 时需要抗混叠转换。
192/384k 是软件 PCM／端点能力检查，不代表 LDAC 协议新增了这些采样率。

已通过 131 项协议、连续性、时间线及端点相关回归；新增信号检查覆盖 8–384k 同率逐样本相等、
44.1/96k 来源同时混合、96k 高频成分保留、96/192k 到 48k 的抗混叠、跨采样率热切换和准备期不消费旧队列。
必要重采样的双声道解析信号误差低于 `4e-7`；同率路径没有额外量化，限制器前视仍为约 1.5ms。
旧版 48k 基线与实际新版原生库摘要保留在本地数值报告中。


## 第三阶段记录

生产语音改用编码器原生 PCM：CVSD 8k、mSBC 16k、LC3-SWB 32k，7.5ms 传输帧不变。
旧 48k 创建与整数接口保留，原生模式绕过多余的 codec 前后 SRC。采集端可保留实际 float 采样率，
麦克风与系统声音在各自源时钟上进入统一语音目标；96k／44.1k／48k 麦克风跨端点切换不改变语音会话。

插值采用控制侧生成的双精度 Kaiser 相位值／导数与 Hermite 插值；双声道系数共享，SSE2 成对卷积，
回调左边界一次准备，避免每个 tap 重复求环下标。更低语音输出采样率使用独立通带／抗混叠设计。
增益和混合累加保留 double，到输出边界才舍入为 float；普通 PCM 不添加抖动噪声。
单声道解码在同率时显式等增益复制到两声道；采集立体声取平均时先用 double 相加。

- 20kHz 内分数插值最大复数误差约 `7.02e-8`（原基线 `1.56e-6`），同率逐样本透明仍成立。
- CVSD 原生 HCI PCM 字节／float 可精确对应；mSBC 原生解码与独立 FFmpeg S16 参考逐样本相等。
  LC3 float 能保留低于 S16 步进的非静音输入；这些检查不把有损编码本身宣称为无损。
- 76 项信号／原生语音／格式边界检查、103 项时间线／连续性／恢复／原生运行时回归通过。
- 同条件 200ppm 漂移对照中，双路 48k 10ms 回调的中位开销约 108µs，旧版约 120µs；
  新版双路 96k 约 216µs。计时包含 ctypes 和系统调度；不代表蓝牙端到端延迟。
  无丢弃、欠载或回调周期搜索，正常限制器前视仍约 1.5ms，未以扩大用户缓冲换稳定。


## 第四阶段记录

LDAC 原生工作线程现按 RTP 时间补齐缺失时长，区分丢包、坏包、重复／乱序和前后跳转。
RTP 时间恒定的来源仅在明确序号缺口时按前包时长作有界估计；正常递增时间戳优先。
短补偿最多延续 20ms，非周期内容快速淡出，超过预算保持真实缺失时长的静音；有效音频
在 4ms 有限窗口内衔接。完整包验证／解码成功前不发布部分 PCM 或缺口。
大跳转重置该来源的解码／转换状态与 PCM 代际，不影响其他来源。

真实供给、补偿、丢包、错误和重新定位分别计数。LDAC 子进程重建不再让累计错误与供给计数回退，
多设备保护不把补偿样本当作有效供给。不同采样率的混音／恢复诊断统一为公共 48k 时间单位，
输出方案更换后仍保持累计计数；退役方案不继续拖大历史复制工作量。

44.1/48/96k 的真实 LDAC 丢包对照证明：总时长不缩短，4ms 恢复窗口后与无丢包参考逐样本相同；
较长缺口的 20ms 之后为零，不无限复制波形。RTP 回绕、前后跳转、显式重启无旧声音残留通过。
44.1/96/192k 回调期限缺口只过期一次，窗口外逐样本恢复，回调不搜索周期。
本阶段 68 项保真／时间线／格式检查通过，其中 13 项新增恢复信号与进程代际检查。


## 第五阶段记录

完整固定源码重建后，全量 751 项通过（0 失败／错误／跳过），Ruff 与版本一致性通过。
全量检查发现并修复了 44.1k 有理相位边界多记一帧、异常析构时端点方案早于混音器释放的问题；
新增分配失败探针逐项证明准备失败保留旧 PCM，最后一个端点引用释放后没有原生分配残留。

最终二进制验证：48k 两小时、96k／192k→96k／44.1k→96k 各半小时虚拟时间，
两种 ±500ppm 时钟均无欠载／丢弃，左右相位误差为零。连续两分钟 AAC＋LC3 双工回放包含
181 次丢包、±3ms 抖动和 7 次两秒 Python 阻塞，零解码错误、队列丢弃、期限缺口及预热后整段静音。
再注入 6 次 10ms 原生解码线程阻塞时，记录一次约 3ms 的期限缺口；补偿／过期量一致，
无重缓冲、回调周期搜索或解码错误，恢复窗口有界。强制阻塞与正常播放的判据分开，保留真实缺口计数。

最终同条件双路 48k 异步转换中位 108.7µs（旧版 118.1µs），双路 96k 215.8µs，
八路首次呈现缺口回调中位 54.85µs、p99 60.99µs，周期搜索为零。
信号、期限、资源和时钟同时作为验收约束；不通过降低协商音质或增加用户缓冲取得这些结果。
