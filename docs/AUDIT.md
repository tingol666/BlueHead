# 音频与生命周期审查

## 2.0.0待验收候选

本轮目标是原生化音频处理、保持既有恢复和热切换边界，并减少发布依赖。Python继续承担Bumble控制与USB包分派；原生音频不意味着整个蓝牙栈已移出Python，也不等于硬实时或保证不存在隐藏缺陷。

| 审查项 | 处理与边界 |
|---|---|
| 旧mixer全局锁竞争导致整块静音 | 转为逐来源有界队列、原子参数与单渲染消费者；仍需完整新包长期播放验证 |
| 非48kHz端点转换 | 保留Windows共享自动转换；拒绝时按端点时钟用Speex，不静默启用另一条通用SRC |
| 高频PCM处理与体积 | 媒体/语音/SRC/mix/WASAPI迁原生；发布移除PyAV/NumPy/sounddevice，开发对照依赖保留 |
| 设备释放与并发 | 候选prepare不start；关闭join回调后释放，采集read/stats与close串行，Context最后关闭 |
| 卡住的系统打开阻止进程退出 | 自有daemon控制队列/Future，避免ThreadPoolExecutor的atexit隐式join；不误报超时后晚提交 |
| 桌面自包含体积 | net48 x64使用目标Windows自带Framework；保留WPF/WinForms/COM，不裁框架DLL |
| Framework兼容安全语义 | 参数正确引用、UTF-8、原恢复hash、原子File.Replace及自有job子树保留；新增检查复现并修复退出事件竞态 |
| AVRCP状态与增益 | 未知播放状态禁用，不猜toggle；标准0–100%音量与0–200%接收增益独立；迟到事件不创建设备卡片 |
| 新协议范围 | 标准Apple音频路径、AVRCP和HFP LC3-SWB实现待真机；LC3-SWB不等同完整LE Audio或产品认证 |

2026-10-26阶段记录：WPF状态/渲染自检98项通过（保留原85项），Framework兼容边界17项通过，native设备离线检查17项通过；独立helper只读枚举通过。范围包括生成音频、临时文件/测试自有进程和界面演示，不包含真实音频播放、移动设备连接或驱动更换。其余协议、原生codec、打包及完整回归结果以最终候选VALIDATION为准，不能把阶段结果拼成未执行的最终验收。

仍需用户验收完整新包：双向语音、挂断媒体恢复、设备热切换/插拔、AVRCP、支持LC3-SWB的对端、多设备、Apple应用路由、驱动恢复与安装升级。长时无线压力、控制器覆盖和端到端延迟也需要单独证据。2.0.0未上传GitHub Release，1.2.4保留为回退。

## 1.2.4（历史实现）

本轮检查播放与采集回调、软件格式回退、混音统计及原生状态所有权。播放和麦克风回调中的 Python 分配、转换和路由锁已移到原生核心或工作线程；统计改为原子快照，重复门控跳过临界区。SpeexDSP 使用固定提交和质量级别，初始化后不在回调中改变格式或分配缓冲。

模拟测试验证任意块长、带外抑制、非有限数、采集环形溢出、停止后的迟到数据和异常关闭。PortAudio 关闭失败时可能已移除或释放句柄，因此保留回调状态、阻止重新初始化，不重试该句柄；退出进程后回收。普通尚未进入底层关闭的可重试失败仍沿用原有保留和重试机制。

本轮未改 USB 传输、HFP 协商或驱动绑定源码，完成离线检查，不进行实机音频验收。具体数量、性能和封包结果见 1.2.4 的 VALIDATION.md，不能视为无缺陷保证。

## 0.2.0 Beta 3（历史记录）

2026-10-25，针对通话恢复、热切换、设备插拔、关闭、后台协议及驱动恢复路径复查。本轮修复四类问题，不作“没有任何隐藏 bug”的承诺。

| 问题 | 修复前证据 | 修复 |
|---|---|---|
| 打开新端点超时后仍晚切换 | 使用原来的真实 20 秒期限，调用报超时后继续等到打开返回，原路由仍被改成新设备 | 为请求建立取消与提交边界；未提交的迟到结果关闭，已进入系统切换的操作等待真实结果；完成与超时同时发生时读取实际结果，避免误报失败 |
| 失败的端点与关闭资源未清理 | 新端点启动失败后回退默认，失败流 closed=false；关闭异常后不能正确重试 | 回退前关闭失败流；尚未释放的原生对象保留回调引用并重试，阻止在残留活跃句柄下重建 PortAudio；关闭请求阻止重新激活 |
| 迟到状态重新创建设备卡片 | WPF 自检中断开/停止后再注入通话与麦克风事件，设备卡片重新出现 | 仅接收中的连接事件创建卡片，忽略陌生设备的迟到状态 |
| 同一端点身份下的停流漏检 | 监视器原来只比较端点 ID；快速拔插或驱动重置可让旧流停止而 ID 不变 | 检查应当运行的真实流状态，发现停止则重建本机音频；使用真实音频流 abort 注入验证检测与三次恢复 |

新增检查先在旧逻辑上复现失败，再验证修复。Python 回归、WPF 状态测试及实际本机双向音频验证的最终数量、结果见同版本 Release 的 VALIDATION.md。

Beta 2 的手机双向通话、两次挂断后媒体恢复、输入输出切换、耳机插拔跟随及驱动恢复重装已获用户确认。Beta 3 是本轮审查修复；两者的验证记录分别标明版本，不能把旧版手机结果伪称为新版重新实测。

本轮没有改变 HFP 协商、SCO USB 缓冲布局、媒体编码算法或驱动绑定流程。驱动代码和本机恢复记录复核通过；驱动失败回退、用户取消与卸载保护仍保留。缺少真实多手机并发、全部控制器覆盖、长时间压力与端到端延迟专项测量，仍是后续测试范围。
