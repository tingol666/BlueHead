# 蓝牙固件、启动与恢复

BlueHead 按实际控制器和 Windows 设备状态工作，不依赖某台电脑、安装目录或固定型号。
USB 能被识别、驱动显示正常，只说明接口存在，不代表运行固件与蓝牙协议已经就绪。

## 日常使用

点击“开始接收”后，唯一的原生 USB 所有者检查控制器、加载匹配的 RAM 固件，再验证标准 HCI 的版本、功能、缓冲与地址。已在运行的固件通过检查后直接使用。此过程不刷写硬件闪存，不改变协商媒体编码、采样率或音频缓冲设置。

需要额外准备时，首页显示“检查蓝牙启动”。点击后直达“启动检查与固件”：

- **获取固件并重试**：从目录指定的 HTTPS 来源获取匹配文件，校验后重新开始接收。首次需要联网，之后使用已验证缓存。
- **从原厂包提取**：选择 ZIP、CAB、MSI 或含静态 CAB 的驱动包。只读取数据，不运行安装程序、DLL 或 MSI 自定义动作；内容仍须与可信目录的长度和摘要一致。
- **原厂驱动引导**：请求管理员授权，恢复原驱动并等待 Windows 蓝牙就绪，再切回专用接收并检查同一个物理适配器。
- **重试接收**：适用于连接或启动时序已恢复的情况。不会隐藏校验错误。

未知格式、未记录的固件版本和不匹配的板卡配置不会被强行加载。可改用原厂驱动引导、系统共用媒体接收，或其他适配器。实时能力不足以支持语音时，程序明确提示“仅媒体接收”，保留用户的语音与音质偏好。

## 原厂引导与系统恢复

原厂引导只进行一次驱动交接。部分控制器切换驱动时会重置并丢失 RAM 固件，因此交接后的原生复核不能省略。若复核不通过，恢复系统蓝牙并解释下一步，不反复切换驱动，也不把“WinUSB 绑定成功”当作“音频已经可用”。

恢复系统蓝牙时会核对原驱动和 Windows 无线电状态，必要时仅重启目标设备一次。若驱动恢复完成但仍不能初始化，则显示 **“驱动恢复完成，请重启电脑”**。应用不会自动重启 Windows，也不会要求重复执行已经完成的恢复。

驱动操作各阶段和原厂备份保存在受保护的 `%ProgramData%\BlueHead\Drivers`。普通用户不能伪造恢复记录。中断的准备会在界面提示检查或恢复，备份不会随程序关闭而删除。后台不可用时运行 `BlueHead.exe --recovery`。

## 固件来源与边界

可信目录位于 `bluehead/assets/firmware/catalog.json`，由独立的 P-256 签名验证，内置公钥在原生代码中。目录固定文件长度、SHA-256、芯片与板卡条件、镜像／配置配对、许可证及上游修订。多个条件同样匹配时拒绝猜测。下载限制来源、重定向、响应大小和时间；缓存每次使用前复核，写入采用原子提交。

最小运行包只内置必要资源；其他镜像按需获取，不把完整固件仓库放入安装包。可选文件和许可保存在用户的 `%LocalAppData%\BlueHead\Firmware` 内容缓存中。公开源码只包含公钥和签名，维护者私钥不进入 Git、源码 ZIP 或安装包。可信目录随应用版本更新。

原生初始化目前覆盖受支持的 Intel secure-TLV 与 Realtek v1 epatch 配置；已初始化的其他厂商经典 USB HCI 控制器使用标准探测路径。具体芯片条件、格式和证据见 [兼容架构与矩阵](COMPATIBILITY.md)。未知型号可有明确降级路径，但不能把矩阵理解为所有硬件均已实测。
