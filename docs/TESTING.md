# 验证范围

自动检查验证协议、编码器与解码器、输入输出切换回退、SCO 分片、USB 原生边界、媒体生命周期和混音。它们不能证明所有手机、控制器或无线环境都兼容。每次发布的具体结果见 Release 的 `VALIDATION.md`。

```powershell
.venv\Scripts\python.exe -m pytest tests -q --tb=short
.venv\Scripts\python.exe tools/audio_benchmark.py work/audio-benchmark.json
```

完整包可运行：

```powershell
BlueHead.exe --self-test C:\Temp\BlueHead-ui
BlueHead.exe --engine-smoke C:\Temp\BlueHead-smoke.json
app\BlueHead.DriverHelper.exe --self-test
```

CLI 报告路径请用绝对路径。UI 自检会生成标明“界面示例”的演示截图，不会连接手机或修改驱动。engine-smoke 检查真实冻结后台的协议握手、只读设备枚举和正常退出。

本机可另运行 `tools/duplex_thread_probe.py`：打开真实麦克风、输出静音并计数，验证后台线程、mSBC 编解码、输入输出热切换与关闭；不保存采集的声音。`tools/audio_switch_probe.py` 另检查无效端点的回退。执行这些检查前应关闭其它接收器。

USB 检查仅在已经绑定 WinUSB 的测试适配器上手动执行：

```powershell
app\engine\BlueHead.Engine.exe --usb-voice-check usb:8087:0033#0+sco=0 C:\Temp\BlueHead-usb.json
```

这会暂时独占并初始化适配器，改变 USB ISO alternate setting，随后关闭。它不建立手机通话；设备 VID/PID 必须与实际一致。CI 不运行任何硬件或驱动操作。

## 真机发布验收

1. 用完整新包连接 Android。播放媒体至少一分钟，记录实际协商编码，暂停/继续后没有残留声音。
2. 开始微信语音，保持至少 30 秒；确认手机声音传到电脑、电脑麦克风传到对方，蓝牙选项保持可用。
3. 通话期间切换真实播放设备和麦克风，再切回默认；无需蓝牙重连，双向声音继续。保持接收，插拔耳机并确认默认选择跟随系统、列表刷新；指定设备保持身份，拔除时回退默认。挂断后回到播放器继续播放，至少重复两次。无效端点应保留原设备并提示失败。
4. 退出到托盘再打开、停止/开始、关闭程序后重新启动，确认无孤立后台、无闪退。
5. 停止接收，在适配器页恢复系统蓝牙；检查设备服务/问题码和系统蓝牙可用，再启用专用接收并重复媒体与通话。
6. 验证取消 UAC、断开适配器、备份不可写等错误能清楚提示；备份失败不得开始绑定。需重启时先重启再继续。
7. 安装、关闭托盘程序后升级、卸载。卸载前需恢复的驱动未恢复时，保留程序；个人设置与配对不删除。

多设备混音、长时间稳定性及实际端到端延迟需单独实测，不能由控制器蓝牙版本推断。延迟可用相同源信号与双通道录音进行相关性测量，必须报告播放/采集设备、编码和无线条件。基准脚本只测混音渲染耗时，不是蓝牙延迟。

## 音量与电脑声音混合

`tools/loopback_probe.py REPORT.json` 使用两段低音量测试信号确认目标进程及子进程被排除、其他进程可收录；只保存数字，不保存声音。`tools/advanced_duplex_probe.py` 使用外部进程测试信号，通过实际 WASAPI 采集、16 kHz 重采样、增益与 mSBC 编码验证 0/100/200%、每设备增益、输入输出热切换与三次本机流重建，仍不连接手机。

手机验收另检查：挂断恢复不再出现 InvalidDataError；卡片码率随实际播放变化并在停止后归零；每台设备上下行 0/100/200% 独立；三个总控均生效；高级模式中其他电脑应用与实体麦克风都能传给对方，而 BlueHead 收到的手机/平板声音不会通过数字回路返送；通话中开关高级模式、切换声音设备无需重连。

## 多设备与默认窗口

0.2.1 增加双 AAC/SBC 协议混音、AVDTP Suspend 单设备策略、选中设备切换和断开接替、AAC 192 kb/s 能力与解码、受损竞争媒体隔离和恢复、旧会话迟到回调及重连线程清理等回归。默认窗口按显示器工作区和 DPI 计算；自动检查覆盖实际工作区、多个分辨率及缩放、小屏、竖屏与保留手动缩小尺寸。几何检查不代替全部真实多显示器组合。

真机复验还应连接两台移动设备：默认高清同时播放不稳时，在首页选择 AAC 后应用并重连；在首页与编码同一行切换“多设备同时播放／单设备自动接替”，验证设备卡片的播放选择；再测 AAC 192 kb/s、微信双向语音、挂断媒体恢复和输入输出热切换。更换编码在语音、声音设备刷新或未完成切换期间应禁用。


## 1.2.2 紧凑界面与接替

界面自检验证接收状态与主按钮同中心线、模式和编码同排、设备两行无额外间距、播放标记紧跟名称、音量操作按两行整体居中、详情弹层不增加卡片高度。小窗口与长名称场景验证省略和操作边界，仍检查独立音量、静音恢复、命令顺序、语音期间编码修改保护和显示器 DPI 约束。

自动接替测试用三台虚拟控制器运行真实 AVDTP，验证 A 主动暂停后 B 恢复并解码出非零 PCM、A 新播放请求可在 B 无包后接替、用户暂停不循环重启。另覆盖语音优先和结束宽限、只有一个来源直接恢复包时仍可播放、远端暂停取消等待及旧会话迟到回调。

真机步骤：选择“单设备自动接替”，先 A 播放，再在 A 仍播放时启动 B；暂停 A，确认 B 自动发声。B 播放时重新启动 A，再暂停 B，确认 A 接替。观察没有碎音或来回切换；再做微信双向语音、通话中输入输出热切换、挂断媒体恢复。回归通过与最终无线验收分别记录。


2026-10-25，最终 1.2.2 日常绿色包按上述流程获用户确认：两次自动接替均正常，微信双向语音、输入输出热切换和挂断后媒体恢复均正常；匿名结果随 Release 的 checks/user-acceptance-1.2.2.json 提供。此次未单独确认实际编码或端到端延迟。
