# 验证方法与边界

公开仓库包含完整产品和构建材料，以及产品内置的离线音频／界面诊断。维护用回归测试、信号参考生成器、开发探针和长测原始数据保留在开发环境，不进入 GitHub 当前源码树和 Source ZIP。构建不依赖这些文件。

## 干净构建检查

按 [BUILDING](BUILDING.md) 构建原生组件及桌面，然后执行版本一致性、静态检查和内置离线诊断。GitHub Actions 也执行这些可从公开树复现的检查。冻结后的后台再次运行相同离线诊断，并由 `tools/audit_package.py` 检查版本、依赖、许可证、固件与文件边界。

## 维护验证覆盖

软件回归覆盖协议帧与真实虚拟控制器信令、ISO 分片和信用、连接代次／句柄复用、持续收发、时钟漂移、Python 与原生线程阻塞、丢包抖动注入、端点事务／热切换、复杂停止与恢复。信号验证包含逐样本对照、重采样频响、静音／弱信号、空声道、高采样率与精细量化，以及独立编码／解码参考。

实时详情还校验原生包计数、按时间计算的速率、暂停归零、实际缓冲与配置预算的区别。指定电脑声音来源校验事务失败保留原路由，以及输出切换前关闭返送路径。

加速虚拟时钟不是小时级真实播放；软件处理时间和缓冲配置不是声学延迟；测试通过不等于所有控制器、厂商和操作系统均互通。每次 Release 的 `VALIDATION.md` 只记录当次实际执行的检查和范围。

## 设备兼容性检查

请针对自己的适配器、固件、发送设备和应用组合检查：

1. 重启后开始接收，持续播放，记录实际协议、编码、采样率和输出设备。
2. 双向语音与录音／录像应用路由、输入输出热切换、语音结束后继续媒体。
3. 多设备同时播放、单设备自动接替、独立音量和静音。
4. 电脑声音与麦克风混合，无数字返送；指定来源被拔出或与输出冲突时的处理。
5. AVRCP 控制／元数据／标准音量；LE 单播上下行、公开与密码广播、节目切换和同步丢失恢复。
6. 停止／重新开始、恢复系统蓝牙、再次启用专用蓝牙、需要重启时的说明。

蓝牙版本号和产品宣传不能替代实际能力检测。兼容性按证据记录，避免把某一台机器的通过结果推广到所有设备。
